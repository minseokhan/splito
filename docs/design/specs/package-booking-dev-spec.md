# Splito · 패키지 예약 연동 — 개발 전달 문서

디자인 레퍼런스: `Splito App.dc.html` › 1a 프로토타입
(왼쪽 목록: 여행 만들기 시작 / 패키지 예약 불러오기 / 선결제 등록 / 여행 상세 / 여행 방 설정. 왼쪽 아래 '데모' 버튼으로 방 종류와 조회 결과를 바꿔 볼 수 있음)
예시 데이터는 모두 가짜이고, 하나투어 예약 조회 API가 연동됐다고 가정함.

---

## 0. 대원칙
- 예약을 연동하지 않은 여행 방은 기존과 똑같이 보인다(일정 영역 없음).
- 정산·예산·통계 계산은 기존과 동일하다. 일정 연결 여부는 어떤 계산에도 영향을 주지 않는다(표시용 메타데이터).
- 동행은 자동으로 초대하지 않는다. 기존처럼 QR·카카오톡·링크로 초대하고, 각자 가입한다.
- 일정은 API 다시 불러오기가 아니라 사용자가 직접 수정한다(아래 6장).

---

## 1. 여행 만들기 시작
- 진입: 홈 우상단 +, 홈의 '새 여행' 카드.
- 선택지 2개: [직접 만들기] → 기존 만들기 화면 / [패키지 예약 불러오기] → 예약 조회.

## 2. 패키지 예약 불러오기

### 2-1. 입력
| 필드 | 규칙 |
|---|---|
| 예약번호 | 입력 즉시 공백 제거 + 대문자 변환. 최대 12자. |
| 예약자 이름 | 공백 제외 1자 이상 |
| 개인정보 제3자 제공 동의 | 필수. [보기] → 약관 전문 |

**예약번호 형식 검증**
- 정규식(가정): `^[A-Z]{2}\d{4}-\d{5}$` (예: `HT2410-58213`)
  - ⚠️ 하나투어 실제 예약번호 규격을 확인한 뒤 정규식을 바꿔야 함. 규격이 여러 개면 OR로 허용.
- 비어 있으면 에러를 보여주지 않는다.
- 값이 있는데 형식이 틀리면:
  - 입력칸 테두리 `#D92D20`
  - 아래 문구(빨강, 13px, 경고 아이콘): **"예약번호 형식이 올바르지 않아요."**
- 검증 시점: 입력할 때마다(onChange). 클라이언트 검증을 통과해도 서버 응답이 최종 기준이다.

**[조회하기] 활성 조건** = 예약번호 형식 OK && 이름 입력 && 동의 체크
- 비활성 스타일: 배경 `#E4E7EC` / 글자 `#A0A4AE` (opacity 쓰지 않음)
- 조회 후 입력값을 바꾸면 결과를 지우고 다시 '조회하기' 상태로 돌아간다.
- 조회 중에는 버튼 로딩 + 중복 요청 막기.

### 2-2. 조회 결과
| 결과 | 판단 기준(가정) | 화면 | CTA |
|---|---|---|---|
| 성공 | 200 + 유효 예약 | 요약 카드: 상품명 · 여행지 · 기간(박/일) · 예약 인원 · 결제 금액 | [이 예약으로 만들기] → 선결제 등록 |
| 예약 없음 | 404 / 번호·이름 불일치 | 빨간 박스 "예약을 찾을 수 없어요" + 번호·이름 재확인 안내 | [다시 조회하기] |
| 취소된 예약 | 예약 상태 = 취소 | 빨간 박스 "취소된 예약이에요" | [직접 만들기] |
| 이미 연결됨 | 같은 예약번호가 다른 방에 연결됨 | 회색 박스 "이미 연결된 예약이에요" + 방 이름 | [기존 방으로 이동] |
| 조회 실패 | 타임아웃, 5xx, 하나투어 점검 | 노란 박스 "예약 정보를 불러오지 못했어요" | [직접 만들기로 시작] (패키지 아닌 일반 방) |

- '이미 연결됨'에서 내가 그 방의 참여자가 아니면 → 방 이름을 숨기고 "다른 여행 방에 연결된 예약이에요"로 보여준다. 초대를 요청하라고 안내. *(확인 필요)*
- 조회 실패로 직접 만든 방은 나중에 **여행 방 설정 › 패키지 예약 불러오기**로 연동할 수 있다.
- 개인정보: 예약자 이름은 조회에만 쓰고, 방에는 마스킹(예: 이*지)해서 저장할 것을 권장.

## 3. 선결제 자동 등록
- 방을 만들면 패키지 결제 금액을 **'여행 전' 지출**로 자동 등록한다.
  - 결제자 = 방을 만든 사람, 날짜 = 예약 결제일, 입력 방식 = 자동 등록
  - 태그: `자동 등록`, `예산 제외`
- **예산에는 포함하지 않는다**(항공·숙박이 포함된 금액). 정산에는 포함한다.
- 예약 인원이 2명 이상이면 질문: **"일행 몫도 함께 결제했나요?"**
  - 네(기본값): 금액 전체를 등록하고 예약 인원 수로 1/N 나눈다(예: 2,980,000원 ÷ 4 = 745,000원).
    - 일행 칸(예약 인원 − 1개)마다 [초대](공유 시트) 또는 [이름으로 추가](게스트) 중 하나를 고른다.
    - 칸을 비워 둬도 진행할 수 있다. 빈 칸 몫은 나중에 참여자가 들어오면 연결된다. *(확인 필요: 빈 칸 몫의 정산 처리 방식)*
  - 아니요: **내 몫만** 등록한다(전체 ÷ 예약 인원).
- 1원 단위 나머지는 결제자에게 귀속된다(기존 1/N 규칙과 같음).
- [장부로 가기] → 여행 상세(기간 필터 = 여행 전).

## 4. 여행 상세 (4a 레이아웃)
- 위에서부터: 기간 드롭다운(전체 · 여행 전 · 1~N일차) + 참여자 동그라미 → 총 지출 → 정산 배너 → [공금 지갑][내 통계][초대하기].
- 참여자 동그라미는 최대 4개까지 보여준다. 5명 이상이면 3개 + `+N` 동그라미. 누르면 전체 참여자 팝오버가 열린다.
- **연동된 방에서만** 기간 드롭다운 항목에 그날의 대표 일정 제목을 붙인다(예: `2일차 · 10.21 · USJ`).
  - 대표 일정 = API의 일차 제목. 없으면 그날 첫 일정 이름.
- 일차 탭(박스형)은 쓰지 않는다. 날짜는 기간 드롭다운으로만 고른다.

## 5. 패키지 일정 영역 (연동된 방만)
- 헤더: "패키지 일정" + 하나투어 배지. (다시 불러오기 버튼, 마지막으로 불러온 시각 표시는 없음)
- 기간이 '전체'면 모든 일차를 이어서 보여주고, 특정 일차면 그 일차만 보여준다.
- 일차 소제목: `2일차 · 10.21 (화) · USJ`
- **일정 카드**: 시간 / 일정 이름 / 연필(수정) / 배지(선택관광, 직접 수정) / 포함 사항 칩 / 연결된 지출 목록 / 합계 / [+ 지출]
  - 포함 사항 칩: 포함 항목은 회색 칩 + 체크 아이콘, 불포함 항목은 테두리 칩 + 마이너스 아이콘.
  - 합계 = 연결된 지출의 원화 합(**내 몫이 아니라 결제 총액**). 없으면 "연결된 지출 없음".
- 시간순으로 정렬하고, 시간이 같으면 등록 순서대로 둔다.
- 일정에 연결되지 않은 그날의 지출은 카드 아래 **'그 외 지출'**로 묶는다. '여행 전'은 '여행 전 지출'로 묶는다(선결제 포함).

### 선택관광 · 예정 지출
- `optional = true`이고 연결된 지출이 없으면 → "예정 · 약 N원" + [안 해요].
- 실제 지출을 연결하면 예정 표시는 바로 사라진다.
- [안 해요] → 카드를 숨기고 아래에 "숨긴 선택관광 n개 · 다시 보기"를 보여준다. 숨김은 **사용자별** 설정.
- 예정 지출은 예산에서 빼지 않는다. 통계의 예산 현황에 **'예정 지출 N원 · 선택관광 n건'**으로 따로 보여준다.
  - 집계 = 숨기지 않았고 지출이 연결되지 않은 선택관광의 예정 금액 합. *(확인 필요: 내 몫 기준이면 1/N로 나눌지)*

## 6. 일정 직접 수정
- 진입: 카드의 연필 → 수정 시트 / 각 일차 아래 [+ 일정 추가] → 추가 시트(여행 전에는 없음).
- 필드:
  - 시간: `H:MM` 또는 `HH:MM`. 정규식 `^\d{1,2}:\d{2}$`. 00:00–23:59 범위도 확인할 것.
  - 일정 이름: 필수, trim 후 1자 이상.
  - 포함 사항: 다중 선택. 항공 포함 · 숙박 포함 · 조식 포함 · 중식 포함 · 석식 포함 · 입장료 포함 · 교통 포함 · 가이드
  - 선택관광 토글 + 예정 금액(숫자만 받고 천 단위 콤마 표시)
- [저장] 활성 조건 = 시간 형식 OK && 이름 입력.
- [삭제]는 기존 일정에만 있다. 삭제하면 그 일정에 연결된 지출은 **그 날의 '그 외 지출'로 옮긴다**(지출은 지우지 않음).
- 사용자가 수정한 일정에는 '직접 수정' 배지를 붙인다. 원본 API 값과 수정본을 따로 저장한다(`source: api | user`, `edited_at`, `edited_by`).
- 수정 권한: 방 참여자 모두 *(확인 필요: 방장만 가능하게 할지)*. 수정 내용은 모든 참여자에게 같게 보인다.
- 처음 수정할 때 불포함 칩은 지운다. 포함 사항은 선택한 값으로 대체한다.

## 7. 일정별 지출 올리기
- 카드의 [+ 지출] → 기존 입력 방법 선택(영수증 / 카드 문자 / 말로 / 직접) → 확인하고 나누기 → 저장.
- 입력 화면 위쪽에 칩으로 "저장하면 **{일정 이름}** 일정에 연결돼요"를 보여준다.
- 하단 [지출 올리기](카드 밖)로 들어오면 일정 연결 없이 저장된다. 연동 방이면 결제일의 '그 외 지출'로 간다.
- **날짜 불일치**: 결제일(영수증·문자에서 읽은 날짜)이 일정 날짜와 다르면 저장할 때 바텀시트를 띄운다.
  - [이 일정에 넣기] → 일정에 연결
  - [결제일(n일차) 그 외 지출로 넣기] → 연결 없이 결제일 기준으로 저장
  - 결제일이 여행 기간 밖이면 '여행 전'으로 넣는다.
- **포함 사항 중복**: 일정 포함 사항에 조식·중식·석식이 있으면 저장 버튼 위에 한 줄 안내를 보여준다.
  - 예: "이 일정은 석식이 포함돼 있어요. 따로 결제한 게 맞나요?"
  - 저장은 막지 않는다. 입장료·교통 등으로 넓힐지는 *(확인 필요)*.
- 연결 정보는 지출의 `schedule_id`(nullable) 하나뿐이다. 정산·예산·통계 계산에서는 이 필드를 무시한다.

## 8. 여행 방 설정
- 진입: 여행 상세 우상단 ⋯
- 공통 항목: 여행 이름 / 기본 통화 / 기간 / 참여자
- 연동된 방에서 추가로 보이는 것:
  - 예약 카드: 하나투어 배지 · '연결됨' · 상품명 · 예약번호 · 인원 · 마지막으로 불러온 시각
  - [예약 정보 다시 불러오기]: 사용자가 수정한 일정은 덮어쓰지 않는다. API에서 바뀐 항목만 반영하고, 충돌 처리 규칙은 *(확인 필요)*.
  - [연동 해제] → 확인 시트 → 해제
    - 사라지는 것: 일정 영역, 예정 표시, 기간 드롭다운의 일정 제목
    - 남는 것: 모든 지출(선결제 포함), 정산, 지출의 `schedule_id` 값(재연동에 대비해 보관하거나 null로 지움 — *확인 필요*)
- 연동되지 않은 방에서 보이는 것: [패키지 예약 불러오기] → 2장 조회 흐름. 성공하면 이 방에 붙인다(새 방을 만들지 않음).

## 데이터 모델(제안)
```
trip_booking      { trip_id, provider:'hanatour', booking_no, holder_masked, product_name,
                    destination, start_date, end_date, pax, paid_amount, paid_at,
                    status, linked_at, last_fetched_at }
schedule_item     { id, trip_id, day_index (0=여행 전), time, title, includes[], excludes[],
                    optional, est_amount, source:'api'|'user', edited_by, edited_at, deleted_at }
schedule_hide     { schedule_id, user_id }            -- [안 해요] (사용자별)
expense.schedule_id  nullable FK
expense.flags     ['auto_prepay','budget_excluded']
```
- 예약번호는 `provider + booking_no`로 유니크(한 예약 = 한 방).

## 확인 필요 목록
1. 하나투어 예약번호 실제 규격과 정규식
2. '이미 연결됨'일 때, 그 방 참여자가 아니면 어떻게 보여줄지
3. 선결제 빈 일행 칸 몫의 정산 처리
4. 예정 지출 집계를 총액으로 할지, 내 몫으로 할지
5. 일정 수정 권한(전원 / 방장)
6. 다시 불러오기와 사용자 수정의 충돌 규칙
7. 연동을 해제할 때 `schedule_id`를 보관할지, 지울지
8. 포함 사항 중복 안내를 식사 외 항목까지 넓힐지
