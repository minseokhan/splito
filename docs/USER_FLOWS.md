# 유저 플로우 · 유저 저니 · 유스케이스

> 기능 정의와 정책은 `PRD.md`, 화면 구현 구조는 `ARCHITECTURE.md`를 따른다. 이 문서는 사용자가 실제로 어떤 순서와 상황에서 앱을 쓰는지 정의한다.

## 1. 화면 맵
```
[앱 실행]
 ├─ 비로그인 → 로그인(카카오 / 네이버 / Apple-iOS) → (신규) 약관 동의 → 프로필 설정(닉네임·계좌 선택)
 │                                                     └→ 대기 중인 초대가 있으면 합류 확인 시트 / 없으면 내 여행 목록
 └─ 로그인 → (대기 중인 초대 있음?) → 합류 확인 시트 / 내 여행 목록

[내 여행 목록]  탭: 진행 중 · 정산 완료 / 카드: 방 이름·기간·내 순잔액 / + 여행 만들기 / 우상단: 내 정보
 └─ [여행 만들기] 이름 · 기본 통화(여행지 국가 추천) · 기간(선택) → 장부 홈

[장부 홈 (방)]  상단: 방 이름·상태 칩·총지출(원화)·내 순잔액 / 초대 버튼 / 방 메뉴
 ├─ 배너 영역: 올리지 못한 지출 N건(P1) · 작성 중인 지출 1건 · 환율 대기 N건 · 합류 후 기존 지출 포함 안내(P1)
 ├─ 피드(날짜별 그룹, "여행 전" 그룹, 실시간) — 행: 가맹점·원화·결제자/기록자·배지·안 읽은 댓글 점
 │    └─ [항목 상세] 원본 사진 · 박스 · 결제자 · 대상 인원 · 환율 근거 · 댓글 · 수정 이력 · 수정 · 삭제
 ├─ FAB + 지출 추가 → [입력 방식 시트] 사진 / 문자 붙여넣기 / 음성 / 직접 입력
 │    └─ [인식 중] → [확인·수정] → 저장
 ├─ 정산 탭(참여자 2명 이상, 게스트 포함) → 사람별 낸 돈·부담액·순잔액 → 송금 카드 → 복사 → 보냈어요/받았어요
 └─ 방 메뉴 → 방 정보(방장 수정) · 멤버(초대·게스트 추가·링크 재발급·목록·내보내기) · 공금 지갑(2명 이상) · 내 정보 · 방 나가기

[초대 링크 진입]  https://{LINK_DOMAIN}/i/{token}  (해커톤: splito-trip.vercel.app)
 ├─ 앱 설치됨 → 앱 열림 → (로그인 필요 시 로그인) → 합류 확인 시트 → 장부 홈
 └─ 앱 미설치 → 웹 랜딩 → 스토어 → 설치 → 첫 실행에서 초대 복원 → 로그인 → 합류 확인 시트
```

## 2. 핵심 저니

### J1. 방장: 여행 만들기 → 동행 초대
| 단계 | 사용자 행동 | 시스템 반응 | 감정·리스크 |
|-----|------------|------------|------------|
| 1 | 앱 설치 → 카카오 로그인 | 카카오 인증 → 신규면 약관 동의 화면 | 첫인상이 정해진다. 동의 화면이 길면 이탈한다 → "필수 전체 동의" 체크 하나로 끝낸다 |
| 2 | 동의 → 닉네임 확인 → 계좌는 "나중에" | 프로필 생성 → 내 여행 목록(빈 상태) | 빈 상태에는 "첫 여행 만들기" 하나만 보여준다 |
| 3 | 여행 만들기: "오사카 3박4일", JPY, 기간 | 방 생성, 나 혼자인 장부 홈 | "모든 동행이 앱에 가입해야 정확히 나눠져요" 안내를 한 줄 보여준다 |
| 4 | 초대 → 카카오톡 공유 | OS 공유 시트(카톡 선택), 링크 메시지 | 단톡방에 바로 보낸다 |
| 5 | 동행이 합류하면 | 사람 지정·정산 메뉴가 열리고, 피드에 "민지 님이 참여했어요" 방 활동이 뜸 | "같이 쓰는 장부가 됐다"는 확신이 생긴다 |

### J2. 초대받은 동행: 링크 → 합류
| 분기 | 경로 | 반드시 보장할 것 |
|-----|------|----------------|
| A. 앱 설치 + 로그인 | 링크 탭 → 앱 → 합류 확인 시트(방 이름·초대한 사람·인원) → 장부 홈 | 시트 없이 자동 합류하지 않는다(잘못 누른 링크 방지) |
| B. 앱 설치 + 비로그인 | 링크 → 앱 → 로그인(+가입·동의) → 합류 확인 → 장부 홈 | 로그인·가입 내내 초대 토큰을 보존한다. 가입이 중단돼도 24시간 보존한다 |
| C. 앱 미설치 | 링크 → 웹 랜딩 → 스토어 → 설치 → 첫 실행 → 초대 복원 → 로그인 → 합류 확인 | 복원에 실패하면 "초대 링크 붙여넣기" 입력을 제공한다 |
| D. 이미 참여 중 | 링크 → 그 방으로 이동 | 중복 참여하지 않는다 |
| E. 만료·재발급·삭제된 방 | "사용할 수 없는 초대예요. 초대한 분께 새 링크를 요청하세요" | 이유를 구분하지 않는다(방 존재 여부를 노출하지 않음) |
| F. 정산 완료된 방 | 합류할 수 있다. 상단에 "정산이 끝난 여행입니다" | 기존 지출에 자동 포함되지 않는다(PRD §7.2 대상 인원 고정) |
| G. 예전에 나간 방 | 같은 링크로 다시 합류할 수 있다 | 예전 기록과 이어진다 |
| H. 다른 화면에서 작업 중에 링크 진입 | 작성 중인 지출은 임시 저장된 상태로 두고 합류 시트를 띄운다 | 입력하던 내용을 잃지 않는다 |

### J3. 여행 중: 지출 기록 (가장 빈번)
| 입력 | 흐름 | 소요 목표 |
|-----|------|----------|
| 영수증 사진 | + → 사진 → 촬영/앨범 → 업로드·인식(취소 가능) → 확인·수정 → 저장 | 15초 |
| 카드 문자 붙여넣기 | + → 문자 붙여넣기 → 텍스트 미리보기 → 인식 → 확인 → 저장 | 10초 |
| 결제앱 캡처 | 사진과 같다(앨범에서 캡처 선택) | 15초 |
| 음성 | + → 음성 → 말하기(실시간 자막, 최대 60초) → 멈춤 → 자막 수정 가능 → 인식 → 확인 → 저장 | 10초 |
| 직접 입력 | + → 직접 입력 → 가맹점·금액·통화·품목 → 확인 → 저장 | 20초 |

**확인·수정 화면 공통 동작**
- **결제자**
  - 기본값은 나다. 다른 참여자로 바꿀 수 있고, 공금 지갑이 켜져 있으면 '공금'도 고를 수 있다.
  - 등록된 공금 카드 끝자리와 일치하면 '공금'이 자동으로 선택된다.
  - 결제한 사람이 아직 합류하지 않았으면 "결제한 분을 먼저 초대하세요" 안내와 함께 우선 나로 저장한다('확인 필요'가 붙음).
- **대상 인원**: 기본값은 현재 참여자 전원이다. 해제한 사람은 박스 지정 목록에서 비활성화된다.
- **날짜·통화·금액**: 결제일·통화·금액을 수정하면 환율과 원화 미리보기를 즉시 다시 계산한다(확정은 저장할 때 서버가 한다).
- **확인 필요**: 노란 배지로 표시하고, 탭하면 그 값으로 이동한다.
- **중복 의심**: 상단 배너로 "어제 18:42 이치란 ¥3,280 지출과 같은 결제인가요? [합치기] [별개예요]"를 띄운다. 합치면 금액은 카드 문자의 청구액을 우선하고, 사진은 모두 유지한다.
- **사람 지정**: 참여자가 2명 이상이면 박스마다 아바타 줄을 보여준다. 아무도 지정하지 않은 박스는 "전원"으로 표시한다.
- **실패 처리**
  - 인식 실패·시간 초과·영수증이 아닌 사진이면 [다시 시도] / [직접 입력]을 보여준다. 사진은 유지한다.
  - 오프라인이면 "연결되면 올릴게요"로 기기에 보관한다(P1).
  - 앱이 강제 종료되면 다음 실행 때 "작성 중인 지출 1건" 배너로 이어 쓴다.

### J4. 박스 사람 지정
1. 박스의 `+ 사람`을 탭하면 참여자 체크 시트가 열린다. 아무도 체크하지 않은 상태가 "전원"이다.
2. 여러 명을 선택하면 박스에 겹친 원형 아바타와 "2명 · 1인 ¥1,640"이 표시된다.
3. 항목 전체에서 사람을 빼려면 항목 상단 "대상 인원"에서 해제한다. 대상 인원은 최소 1명이다.
4. "나만 쓴 지출" 빠른 토글을 켜면 대상 인원이 결제자 1명이 된다(P1).
5. 저장 후에도 항목 상세에서 언제든 다시 지정할 수 있고, 변경은 이력에 남는다.

### J5. 의문 해결 (돈 얘기 대신)
- 피드에서 이상한 금액을 보면: 항목 상세 → 원본 사진 확대 → 환율 근거 확인 → 댓글 "이건 뭐야?" 순서로 해결한다. 올린 사람의 피드 행에 안 읽은 댓글 점이 표시된다(P1). 읽음 상태는 서버에 저장하지 않고, 기기 로컬에 지출별 `last_seen_at`을 두고 판단한다. 푸시는 P2다.
- 누가 금액을 바꿨는지 궁금하면: 수정 이력에서 "지훈 · 10/22 21:14 · 금액 ¥3,000 → ¥3,280"을 본다.
- 잘못 삭제한 지출은 이력에서 [복구]할 수 있다(P1).

### J6. 여행 후: 정산 → 송금 → 완료
1. 정산 탭을 연다. 환율 대기·확인 필요 항목이 있으면 상단 경고와 바로가기를 띄우고, 사람별 표와 송금 카드 목록을 보여준다.
2. 내가 줄 사람인 카드에서 [복사]를 누르면 "지훈에게 132,000원 · 카카오뱅크 3333-01-1234567"이 복사된다. 은행 앱에서 송금하고 돌아와 [보냈어요]를 누른다. 금액 기본값은 카드 금액이며, 일부만 보냈으면 수정한다.
3. 받을 사람이 계좌를 등록하지 않았으면 카드에 "계좌 미등록"과 [계좌 요청하기]가 보인다. 요청하면 받을 사람의 방 활동에 표시되고, 탭하면 바로 계좌 등록 화면으로 간다.
4. 받을 사람은 [받았어요]로 확인하거나 [못 받았어요]로 그 기록을 무효로 만든다. 무효가 되면 줄 사람 카드에 "받지 못했다고 표시했어요"가 뜬다. 줄 사람이 체크하지 않았어도 받을 사람이 [받았어요]로 기록을 만들 수 있다.
5. [보냈어요]를 잘못 눌렀으면 받을 사람이 확인하기 전까지 같은 카드의 [취소]로 되돌린다.
6. 전원 확인이 끝나면 방이 '정산 완료'가 되고 목록의 "정산 완료" 탭으로 옮겨진다. 완료되지 않은 인원은 정산 화면에 "확인 대기 2건 · 민지, 지훈"처럼 표시한다.
7. 정산 뒤 지출이 추가·수정되면 '정산 중'으로 돌아간다. 남은 송금만 다시 계산되며, 역송금이 나올 수도 있다.

### J7. 공금 여행
1. 방 메뉴 → 공금 지갑에서 공금을 켠다. 통장 주인을 고르고, 사람별 입금액을 입력하고("같은 금액 일괄 입력" 버튼 제공), 공금 카드 끝자리 4자리를 등록한다(선택).
2. 여행 중 공금 카드 승인 문자를 붙여넣으면 끝자리가 일치할 때 결제자가 '공금'으로 자동 선택된다. 바꿀 수 있고, 문자에 끝자리가 없으면 수동으로 고른다.
3. 정산 화면에 공금은 송금 대상으로 따로 나오지 않는다. 남은 공금은 통장 주인의 송금안에 합쳐지고 "남은 공금 100,000원은 B 님이 돌려줄 금액에 포함됐어요"라는 설명이 붙는다. 공금이 부족하면 "부족한 공금 N원은 B 님이 받을 금액에 포함됐어요"로 바뀐다.

### J8. 늦게 합류한 동행 / 혼자 쓰다가 함께 쓰기
- 기존 지출의 대상 인원은 저장할 때 고정되므로, 새로 합류한 사람은 **기존 지출에 자동으로 포함되지 않는다.**
- 합류 직후 기존 지출이 있는 방이면 장부 홈에 "합류 전 지출 N건은 OO님과 나눠지지 않았어요 [함께 나눌 지출 고르기]" 배너를 띄운다(P1). 지출을 고르면 대상 인원에 추가되고 이력이 남는다.
- 혼자 먼저 출발한 사람의 개인 지출은 그대로 개인 부담이다.

### J9. 앱을 쓰지 않는 동행 — 게스트 멤버 (P0)
1. 방 메뉴 → 멤버 → [게스트 추가]에서 이름("엄마")을 입력한다. 대표자 기본값은 나이고, 다른 가입 멤버로 바꿀 수 있다.
2. 게스트는 아바타에 점선 테두리와 "게스트" 라벨이 붙는다. 박스 지정, 대상 인원, 결제자("엄마가 현금으로 냈어요"), 공금 입금에 고를 수 있다.
3. 정산 화면의 사람별 표에는 "엄마(게스트 · 대표 민지)"가 따로 보인다. 송금 카드에는 나오지 않고, 민지의 송금에 합쳐진다. 카드에 "엄마 몫 포함"이라고 표시한다.
4. 대표자를 바꾸면 "엄마의 정산 금액이 지훈 님에게 옮겨져요" 경고를 띄우고 이력에 남긴다. 대표자가 방을 나가려면 먼저 게스트를 다른 멤버에게 넘겨야 한다.
5. 게스트가 나중에 앱에 가입하면 별도 멤버로 합류한다(계정 전환 없음). 필요하면 게스트에게 지정했던 박스를 새 멤버에게 다시 지정한다. 장부에 쓰이지 않은 게스트는 삭제할 수 있다.

### J10. 이탈·정리
- **방 나가기**: 확인된 송금 기준 순잔액이 0이 아니면 "정산을 마친 뒤 나갈 수 있어요 [정산 보기]"가 뜬다. 통장 주인은 먼저 위임해야 한다.
- **방장이 나감**: 가장 먼저 합류한 참여자에게 방장이 위임되고, 피드에 공지가 뜬다.
- **링크 유출**: 방장이 [링크 재발급]을 하면 이전 링크는 즉시 무효가 된다. 모르는 사람이 들어왔으면 방장이 [내보내기]를 한다(P1). 그 사람의 기록은 남고, 링크는 자동으로 재발급된다.
- **회원 탈퇴**: 정산이 남은 방이 있으면 "정산 중인 여행 N개를 마친 뒤 탈퇴할 수 있어요"와 방 목록을 보여준다. 없으면 확인 문구 입력 후 탈퇴한다.
- **먼저 귀국**: 방을 나가지 않는다. 이후 지출에서 대상 인원을 해제한다. 새 지출의 대상 인원 기본값은 "직전 지출과 같게"를 제안한다(P1).

## 4. 가설
위험도가 높은 순서다. 해커톤 기간에 측정하기 어려운 가설은 **데모 전 실사용 테스트**로 관찰한다. 친구 3~4명이 실제 영수증 20장으로 한 번 써보는 방식이다.

| ID | 가설 | 검증 방법 | 틀리면 |
|----|------|----------|--------|
| H9 | 대부분의 동행은 앱에 가입하고, 게스트는 일부(가족 여행)에서만 쓴다 | 방별 게스트 비율, 초대 후 24시간 합류율 | 게스트가 많으면 게스트에게 정산 링크(웹) 공유를 검토한다 |

## 5. 상태 모델 (사용자에게 보이는 상태)
- **방**: `my_rooms`가 위에서부터 차례로 판정한다.
  1. `정산 완료` = 멤버 2명 이상 ∧ 활성 지출 1건 이상 ∧ 확인된 송금 기준 순잔액 전원 0 ∧ 환율 대기 0건
  2. `정산 중` = 무효가 아닌 송금 기록 1건 이상
  3. `함께 기록 중` = 멤버 2명 이상
  4. `기록 중` = 그 외(1명)

  지출이 바뀌어 1번 조건이 깨지면 자동으로 `정산 중`으로 돌아간다.
- **지출**
  - 작성 중(기기에만 있음, 다른 사람에게 안 보임) → `저장됨`.
  - 배지: `확인 필요`, `환율 대기`. 삭제된 지출은 이력에서만 보인다.
  - `중복 의심`은 확인 화면 배너로만 쓴다(P0). 피드 배지는 P1이고, 클라이언트 `lib/duplicate`로 계산한다.
- **송금 기록**
  - `확인 대기`(한쪽만 기록) → `확인됨`(받을 사람 확인).
  - 무효 상태: `취소됨`(보낸 사람, 확인 전) / `못 받음`(받을 사람).
  - 화면 순잔액에는 확인 대기 기록까지 반영한다. 나가기·탈퇴·정산 완료 판정에는 확인된 기록만 반영한다.
